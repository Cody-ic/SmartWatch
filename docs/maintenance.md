# 维护、发布与交接

## 1. 修改前阅读顺序

先阅读仓库首页、[架构](architecture.md)、[硬件](hardware.md) 和当前 [PCB 核验](pcb-review.md)。在源码工程中继续阅读 `AGENTS.md`、`.cproject`、当前模块头文件与实际调用处；历史 README 和注释可能保留旧模型、旧外设或旧板信息。

本轮已确认并更正的历史差异：睡眠是 280 维二分类，显示是 SPI2，BLE 是 USART1，Gerber 是四层板，H2 显示排针与 CN1 烧录 FPC 是两个接口。

## 2. 三端变更检查

| 改动 | 同步检查 |

## 3. 开发约束

沿用相邻文件的 C 命名和缩进，模块文件为 `snake_case.c/.h`，宏采用大写。LVGL 调用集中在 Sensor 任务。大型数组避免放进有限 RTOS 栈；新增静态缓冲也需要重新检查 RAM 占用。

当前无完整 Git 历史可归纳原有提交规范，可使用 `docs: ...`、`BLE: ...`、`Sleep: ...` 等说明模块和动作。提交应附构建与对应回归结果；UI 改动附界面依据，协议改动说明版本兼容性。

## 4. 发布步骤

1. 固定三端源码版本和依赖，确认工程型号与目标板一致。
2. 完成两个固件构建、Flutter analyze/test 和涉及模块的实际 C 回归。
3. 重新生成并核对 C/Dart 双向 fixture，确认文档字段与实现对应。
4. 记录版本、工具链和功能测试结果。
5. 对目标设备执行写入与 verify，记录设备标识与安装版本。
6. 按设备矩阵完成接口、传感器、空口、异常恢复、续航与告警验收。

软件构建与主机逻辑测试已完成，本轮未重新烧录或完成完整真机功能验收；用户确认实板供电正常，既往烧录异常待定位。

## 5. PCB 新版本交付要求

修改原理图后同步 PCB，关闭 H01/H02/H03 等问题；执行原生 ERC/DRC、更新铺铜、检查未布线，再统一导出工程、网表、全部四层 Gerber、钻孔与飞针表。用同一版本号标记设计资料。

原始文件仅在满足核验条件后作为设计版本上传。当前仓库的硬件目录用于说明发现的问题与整改状态，不能直接用于下单制板。
