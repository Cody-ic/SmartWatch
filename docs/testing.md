# 功能验证与验收

本文按用户实际使用的功能记录验证状态。用户确认实板供电正常，既往出现过烧录异常。本轮未重新烧录或完成完整真机联调；“逻辑测试通过”仅表示自动化测试覆盖的代码行为符合预期。

| 功能 | 当前状态 | 真机操作与通过标准 |
| --- | --- | --- |
| 开机、圆屏与按键 | 固件已实现，待上板 | 开关机与复位正常；页面显示、切换和按键响应正常，无卡死 |
| 心率与实时血氧 | 已实现；血氧过期逻辑已测试 | 正常佩戴能持续更新；移开或停止采样后约 5 秒内撤销旧血氧；重新佩戴后恢复新数据 |
| 睡眠监测 | 二分类与窗口处理已实现，相关逻辑已测试 | 完整采样后产生结果；缺失采样不使用残缺窗口；App 显示最新累计时长，不重复累加；准确性需对照睡眠记录 |

短信测试目前使用模拟通道，未向真实号码发送。Android 调用返回成功表示请求已提交，实际送达需要在接收手机上确认。iOS/Windows 未完成平台验收。

## 2. 已执行的软件功能测试

- **原型传输**：完整帧、重复/乱序片、丢失确认后的重试、超时、旧事务隔离、错误数据拒绝，以及失败时保留旧模型。
- **采样与时效**：无新样本时血氧失效、计时器回绕、30 秒睡眠窗口、结果只消费一次、缺失 PPG 时拒绝窗口。
- **蓝牙桥接缓冲**：空间不足时拒绝整个写入，避免只写入部分数据造成后续协议错位。
- **App 行为**：联系人迁移、权限拒绝、短信正文、旧血氧清除与累计睡眠显示。
- **跨端互通**：Dart 生成的数据由生产 C 解析，C 生成的数据由 Dart 解析，检查两端字段和内容一致。

已执行结果为两份固件构建通过、Flutter 静态检查通过、18 项 App 测试及 11 组 C 回归通过、Android Debug APK 构建通过。测试源码见 [C 回归](../firmware/stm32/tests/host/) 和 [App 测试](../app/flutter_app/test/)，运行命令见 [构建说明](build.md)。
