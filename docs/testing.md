## 2. 生产 C 回归覆盖

`tests/host/firmware_regression.c` 直接编译生产 UART、原型模型、睡眠模型、睡眠特征和 SpO2 代码；`ch582_fifo_regression.c` 直接编译 CH582M FIFO。HAL、RTC 与无关接口由 stub 替代，没有重新写一套算法来充当被测实现。

测试覆盖：短恢复包保留旧模型；128 字节完整帧；乱序与重复片；丢失最终 ACK 的重试；CRC 错误；合法 CRC 包含 NaN；冲突重复；事务超时与隔离；接收溢出后的状态恢复；无新样本时的 SpO2 超时及 tick 回绕；120 批原始 IMU 形成 30 秒 epoch；就绪标志一次消费；缺失 PPG 窗口拒绝；FIFO 满和部分空间拒绝、16 位索引回绕。

测试结果不模拟真实 DMA 时序、中断抢占、传感器电气行为或无线空口。测试编译使用主机架构，Cortex-M33 / RISC-V 的实际运行由后续设备验收覆盖。

## 3. Flutter 回归覆盖

- 不对齐的原型字节数据仍正确按小端解码，并得到独立数据副本。
- 拒绝错误长度、NaN、原型维度错误和过长外层帧。
- CRC32 已知向量正确；备份需匹配事务并收到每个唯一片段。
- 拒绝短片、冲突重复、整包 CRC 错误和过期会话的旧片。
- 恢复忽略旧事务 ACK、重试丢失 ACK、限制尝试次数、拒绝时停止。
- 新安装不产生联系人；迁移只移除精确匹配的旧示例并保存原始数据。
- 无联系人或无权限不调用短信通道；有效配置使用模拟通道发送佩戴者正文。
- 仪表盘在无效、断连、超时后清除血氧；累计睡眠报告不会重复相加。
- 生产 C 生成的备份帧可在 Dart 中解析并核对各类原型值。

## 4. 双向 fixture 顺序

先由 Dart 的 `test/fixtures/export_restore.dart` 生成恢复字节，交给生产 C 的 UART 回调与解析器验证；C 再生成备份字节，交给 `firmware_interop_test.dart` 验证。fixture 文件随测试生成，不应把旧 fixture 与新协议混用。

完整命令见 [构建文档](build.md)。涉及协议、模型存储或分片修改时，同时更新两端、fixture 和本文中的尺寸/重试说明。
