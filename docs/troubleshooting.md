# 故障排查与已知限制

## 1. 构建工具找不到

PowerShell 普通 PATH 不一定包含 CubeIDE/MounRiver 的 make 和 GCC。按 [构建说明](build.md) 配置当前安装目录，检查所在目录分别为 STM32 的 `Debug`、CH582M 的 `obj`。Flutter 使用本机实际 SDK `D:\Flutter\flutter\bin\flutter.bat`。

CH582M 的工具链目录中有另一份 make；若 `all` 的递归构建失败，改用 MounRiver `others/Build_Tools/Make/bin/make.exe`。不要把这一工具调用错误误报为固件编译错误。

## 2. STM32 网络重复符号或生成代码回退

检查 `.cproject` 是否保留旧 AI 文件排除列表，对照 `Debug/AI/subdir.mk` 和 `objects.list`。同目录下留存的旧 `network.c` 与新模型可能导出相同符号。

若显示/串口/ADC 在重新生成后失效，检查手工引脚迁移是否被覆盖。当前有效映射包括 SPI2 PB13/PB15、USART1 PA9/PA10、I2C1 PB3/PB6、BAT ADC PA2/PA4。`.ioc` 不是唯一真值。

## 3. 既往烧录异常

用户确认实板供电正常，之前遇到的是烧录异常；具体原因尚未定位。本轮没有重新烧录，也不将 MCU 标注型号差异或供电异常作为既定原因。

复测时先记录错误原文和阶段：下载器是否被识别、能否读取目标芯片、在哪一步写入失败、写入后能否运行。再针对对应阶段检查驱动、下载器连接及 SWD 或 TIO/TCK 信号。CN1 没有引出 NRST 和 VTREF；使用 under-reset 时需要实际接入复位信号。

上次更新检查时，STM32CubeProgrammer 报 `No ST-Link detected`，WCH OpenOCD 报 `WLink Open Error`，ADB 设备列表为空；因此没有执行设备更新。这些是当时的工具连接检查结果，不能解释用户此前的烧录异常，也不能据此认定目标板供电故障或固件失效。

板上的 6P Type-C 是供电口，没有接入 MCU USB 数据线；不能期望通过该口直接出现 ADB 或 MCU USB 设备。

## 4. App 扫不到或连上没有数据

确认系统蓝牙和权限，核对广播 FFE0、名称和 FFE3 Notify 订阅。网表 TX/RX 已交叉对应，物理连线仍要实测。CH582M 固件需要与新版服务定义匹配；UART1 禁止调试输出。

App 当前在缺失部分特征时可能仅记录 WARNING，因此“连接返回成功”不等于全部业务链路已就绪。查看日志中的订阅、授时、配置写入、坏帧及解析错误，再检查 MCU 是否持续发布数据。

## 5. 原型备份超时或恢复失败

确认使用 [v2](protocol.md)：先 BEGIN，再分片；备份请求包含事务 ID。旧客户端的单字节备份请求或无 BEGIN 恢复不适用。检查 3586 字节总长、30 片、122/48 字节片长、CRC 和浮点值。

恢复必须收到匹配 id/index 的 ACK，末片必须状态 1。只看 GATT Write 成功不能证明模型已提交。备份方向没有逐片 ACK；缺包会失败，可重新请求并记录协商 MTU、连接间隔与并发负载。

设备重启会清空 RAM 原型。当前所谓出厂命令也是清空存储，不会自动装载通用原型。

## 6. 血氧不显示或睡眠启动慢

血氧缺失可能是 invalid、数据超时、PPG 信号质量不足或链路缺失；新版会主动清除过期值。不能用历史最低血氧代替实时值来掩盖断流。

睡眠特征需积累五个完整有效的 30 秒 epoch；缺失 PPG 的窗口会被拒绝，因此初始化与恢复后不会立即得到结果。当前模型是二分类，其输出必须按 `[Wake,Sleep]` 解释。

## 7. 短信显示已提交但没有收到

联系人为空、权限拒绝时，App 应给出明确状态。原生方法返回表示调用 SmsManager 后没有立即抛出错误，当前没有运营商送达回调。检查 SIM、系统权限和短信应用/系统结果，分别记录“请求提交”和“实际收到”。

## 8. 当前实现限制

| 项目 | 当前状态 | 后续处理 |
| --- | --- | --- |
| 实板供电 | 用户确认正常 | 本轮未重新测量，不列为已知故障 |
| 烧录 | 既往出现异常，原因未定位 | 复测时记录具体错误和失败阶段 |
| PCB 图纸与充电 | 留有接线检查项，电芯匹配尚未确认 | 与实板表现分别记录，见 [PCB 报告](pcb-review.md) |
| 功能模块位掩码 | 可设置和保存在备份寄存器，入口未全面门控 | 不能把 ACK 视为所有子系统已关闭 |
| 原型 | RAM 存储，界面导入/导出流程不完整 | 补齐产品入口与持久化策略 |
| 个人参数 | 连接时发送 65 kg / 22 岁默认值 | 增加持久化与重连恢复 |
| 连接判断 | STM32 UART 超时与 App GATT 状态不同 | 根据需要增加显式链路状态协议 |
| 短信 | 无实际送达回调 | 完善原生结果反馈与验收 |
| 发布签名 | release 配置仍使用 debug signing | 正式发布时配置独立签名与应用标识 |
| 算法与续航 | 缺少当前整机真机数据 | 以参考输入、佩戴实验和功耗测量验收 |

这些条目记录实际代码状态与尚未执行的验证，不表示已完成相应功能修复。
