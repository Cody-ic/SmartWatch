# AI 模型、真机数据与 proto 后训练

## 模型与接口

| 模块 | 当前接口 | 主要实现 |
| --- | --- | --- |
| HAR 活动识别 | 6×512 量化输入，7 类输出 | `har_model`、`har_network`、`har_network_data` |
| HAR embedding | 128 维特征 | `har_embedding` |
| Proto 原型分类 | 7×128 个 float，归一化特征与原型做余弦相似度分类 | `proto_model` |
| KWS 关键词 | 1280 元素量化 MFCC，4 类概率 | `kws_model`、`kws_network`、`kws_network_data` |
| Sleep 睡眠 | 280 个 float，`[P(wake), P(sleep)]` | `sleep_model`，108 树二分类 |
| 心率检测 | PPG 信号处理 | `hr_detector`，结合主控 PPG 采样 |

睡眠特征与血氧处理还涉及 `../Core/Src/sleep_features.c` 和传感器采样逻辑。旧模型文件仍有留存，实际编译集以 `.cproject` 为准；旧文档中的 378 维、三分类睡眠描述不适用于当前模型。

## 参数需要真机数据

现有权重、置信度门限和算法参数是当前实现的起点，尚不能视为整机标定结果。训练集分数不能替代真实佩戴准确率。后续需采集以下数据：

- 活动：带活动标签的连续 IMU、embedding、基础分类结果、置信度与原型输出；覆盖过渡动作和易混淆类别。
- 心率/血氧：原始 PPG、有效采样数量、佩戴松紧和运动状态，配合参考设备记录误差与失效场景。
- 睡眠：连续 IMU/PPG、缺失窗口与对照睡眠记录，检查窗口完整性和判定误差。
- 关键词：实际麦克风录音和识别结果，覆盖距离、音量、佩戴环境与背景声。

每次评估记录设备、固件版本、采样配置、佩戴条件、标签与参考来源。更新所用数据和独立评估数据应分开，避免用同一段数据同时训练和证明效果。

## 后训练路线约定

**后续后训练统一采用 proto（原型学习）路线。** 当前落地对象为 HAR embedding 上的类别原型：保留特征提取链路，利用真机活动样本更新原型，并验证更新后的分类表现。

1. 在 App Session 选择目标活动并开始采集，保存活动标签与对应真机记录。
2. 固件通过 `proto_session_feed_if()` 接受目标 HAR 类别匹配且置信度至少 0.7 的 embedding。
3. 结束会话时至少需要 50 个有效推理样本；不足则不更新。有效推理样本不等于原始 IMU 点，采集时长取决于推理频率及门控通过率。
4. 对有效 embedding 求均值并做 L2 归一化，替换对应类别原型，递增版本与样本计数。
5. 在独立采集记录上比较更新前后的分类表现、误报和类别混淆，再决定是否采用新原型。
6. 通过备份/恢复管理原型，恢复必须收到完整提交确认。

会话实现位于 `../Core/Src/ble_uart.c`，原型存储和分类位于 `proto_model.c/.h`。0.7 置信度和 50 个样本是现有默认设置，需要真机数据验证其适用性。仅依赖基础 HAR 预测的门控可能拒绝本就容易误识别的目标活动，评估时需记录拒绝比例及样本偏差。

## 当前能力边界

当前 Session/proto 更新链路覆盖活动识别个性化；睡眠、KWS 和心率/血氧尚未提供同样的 proto 更新接口，其参数仍需按各自真机数据标定与验证。后训练设计沿用 proto 约定，新增接入点时明确特征、标签、原型结构和评估方法。

`app_init()` 调用 `proto_model_init()` 清空原型，原型保存在 RAM，训练或恢复后不会自动写入 Flash。重启后需重新恢复或采集。App 已有备份拉取入口，完整文件导入/导出界面和持久化流程尚未完成。

## 维护与验证

修改模型时核对输入维度、通道顺序、采样率、量化参数、类别顺序、RAM 和推理耗时。HAR 使用 100 Hz 重采样数据；睡眠使用原始 104 Hz IMU，30 秒一个 epoch，5 个完整有效 epoch 形成 280 维输入；缺失 PPG 的窗口不参与推理。

主机回归验证数据完整性、传输失败保护和窗口处理；模型效果必须用真机数据评估。原型传输格式见 [协议规范](../PROTOCOL.md)，已有功能验证标准见 [仓库首页](../../../README.md#功能验证)。
