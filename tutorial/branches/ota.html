支线四 B：无线固件升级的完整设计

在可靠传输之上增加镜像、Bootloader、存储与掉电恢复。当前项目尚未实现整机 OTA，本章是设计与主机练习。

前置：协议事务、Flash、复位、链接和无线通信。原理 · 实验 · 项目 · 验收
知识：三种更新不是同一个操作知识：镜像与启动决策独立实验：在电脑上模拟掉电从模拟走到真实设备需要补齐什么验收清单检查理解参考资料

知识：三种更新不是同一个操作

更新对象影响范围当前项目
类别原型改变 7×128 类别中心，不改程序指令已有 RAM 更新与可靠传输
模型权重 / 网络可能改变权重、形状、算子与内存布局没有通用动态替换流程
完整应用固件改变可执行镜像，涉及启动与分区尚未实现 OTA Bootloader 与更新流程

无线 OTA 指通过链路传输并由设备完成程序更新，Flash 编程依旧会发生，只是不依赖每次连接下载器。第一次建立可恢复的启动与升级机制通常仍需预置相应固件；不能把一个原型恢复命令直接当成应用升级命令。

知识：镜像与启动决策

Bootloader 在执行应用前决定启动哪个有效镜像。设计需要实际 Flash 容量、页与编程粒度、当前镜像大小、分区与中断向量位置。A/B 或暂存/交换方案有不同空间与恢复要求；这里不提供未经确认的硬编码地址，不自动修改当前链接脚本。

CRC 可以发现偶发损坏，不能证明镜像来自可信发布者；来源验证需要签名等认证机制与受保护的信任根。反回滚、恢复入口与密钥生命周期要纳入设计，不在故障时临时绕过。

独立实验：在电脑上模拟掉电

升级流程伪代码 · 不是可刷入的 Bootloader

# 状态机伪代码：只操作主机上的模拟槽位，不写真实 Flash。
state = 'IDLE'
on_begin(manifest):
    validate_size_version_and_target(manifest)
    state = 'RECEIVING'
on_chunk(index, data):
    write_staging_idempotently(index, data)
on_finish():
    verify_complete_image_and_signature()
    persist_trial_boot_record()
    state = 'TRIAL'
on_app_health_confirmed():
    persist_confirmed_record()
    state = 'CONFIRMED'
  1. 把两个普通文件作为旧镜像与新镜像，定义清单包含目标、版本、长度与校验/认证信息。
  2. 每收到一块就记录状态，重复块必须一致，不允许无界偏移写入。
  3. 在写块、校验、标记试运行、确认等边界模拟程序被强制结束；重新启动模拟器后应能决定下一步。
  4. 损坏清单、截断镜像、模拟错误签名和试运行崩溃，检查仍有可恢复路径。

从模拟走到真实设备需要补齐什么

  • 审查真实分区、链接地址、启动入口、中断向量重定位与具体 Cortex-M33 配置。
  • 按目标芯片验证 Flash 擦写、电源失败行为、看门狗策略和更新期间执行限制。
  • 为 BLE→CH582M→UART→STM32 设计升级背压、断点续传与状态查询；规定两颗芯片分别如何更新与版本配套。
  • 在可恢复的实验硬件上逐项验证，再接入 App 的镜像选择、进度、断连恢复和失败提示。
当前状态本章提供知识与可在主机进行的状态机练习，没有宣称手表已支持完整 OTA，也没有提供会擦除现有程序的操作。现有固件启动方式与分区保持不变。

验收清单

  • 每个升级状态遇到掉电后，能够说明启动哪个镜像以及为什么。
  • 拒绝错误目标、错误长度、损坏内容和未授权镜像。
  • 试运行未确认能回到可用版本，并且恢复入口不会被同一次应用升级覆盖。
  • 记录真实设备的成功与故障测试，才将 OTA 状态从“设计”改为“已验证”。
